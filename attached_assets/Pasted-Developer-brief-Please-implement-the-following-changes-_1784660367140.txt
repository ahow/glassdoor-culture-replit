Please implement the following changes to the culture-scoring and factor-construction pipeline. Before starting, create a full rollback point so we can revert quickly if the new framework underperforms.

Create a saved point before making any changes.

Requirements:

Save a complete snapshot of:

Current company-level and review-level scores.

Please provide:

2) Remove non-Schroders frameworks from active analysis
For the next version, remove Hofstede and MIT frameworks from the active analysis pipeline.

Requirements:

Do not delete their source files permanently if they are part of the rollback snapshot.

Remove them from:

Active scoring runs.

Dashboard outputs.

Aggregation logic.

Model-training inputs.

Client-facing / research-facing summary views.

The active framework going forward should be Schroders only.

3) Keep mined Schroders dictionary as production base
Use the mined Schroders dictionary as the production scoring dictionary for this rebuild, not the expert dictionary.

Reason:

The mined dictionary has much stronger review coverage and materially lower multicollinearity than the expert dictionary.

The mined dictionary shows review hit rates of 5.484% to 27.363% across dimensions, versus 0.058% to 1.231% for the expert dictionary.

The mined dictionary VIFs are 1.22 to 2.67, versus up to 12.02 for the expert dictionary.

Bootstrap diagnostics are also materially more stable for mined than expert.

Requirements:

Keep the expert dictionary archived but inactive.

Ensure all new downstream analysis uses the mined Schroders scores only.

4) Preserve current review-level scoring engine for now
Keep the current review-level text scoring logic unchanged initially, so that we isolate the redesign to the aggregation / weighting / factor-construction layer.

Current scoring logic to preserve:

Same text assembly.

Same regex matching rules.

Same hyphen handling.

Same negation handling.

Same review-level dimension score formula.

Same term weights for the mined dictionary.

Do not change the review scoring engine in this phase unless we explicitly request it later.

For every company × Schroders dimension, compute and store the following:

total_reviews_company

n_scored_reviews_dimension

share_reviews_scored_dimension = n_scored_reviews_dimension / total_reviews_company

Important:

n_scored_reviews_dimension must mean number of reviews where that dimension is non-null / fired.

se_dimension_score_raw should be based on review-level scores contributing to that company-dimension score.

Contribution shares should measure concentration risk, i.e. whether a score is being driven by a very small number of terms or reviews.

6) Introduce company-dimension evidence tiers
Create evidence tiers for each company × dimension using the mined Schroders scores.

Implement exactly these tiers:

Tier A

n_scored_reviews_dimension >= 50

and total_reviews_company >= 150

Tier B

20 <= n_scored_reviews_dimension < 50

or 50 <= total_reviews_company < 150

Tier C

5 <= n_scored_reviews_dimension < 20

Tier D

n_scored_reviews_dimension < 5

Store:

evidence_tier_dimension

Rules:

Tier D dimensions must be treated as insufficient evidence.

Tier C dimensions may remain available for internal diagnostics, but must not feed the client-grade published dimension ranking unless specifically overridden later.

7) Sector-relative framework only
All factor construction must now be sector-relative, not global.

Requirements:

Use the company’s sector classification already present in the panel data.

Build all priors, standardisation, ranking and factor outputs within sector.

Do not create cross-sector comparable culture scores.

Every published score should be interpreted as relative to peers in the same sector.

If sector sample sizes are too small, implement a fallback hierarchy:

Subindustry, if sample size is sufficient.

Industry, if subindustry is too small.

Sector, if industry is too small.

Please make this hierarchy configurable.

9) Build sector-specific financial-performance weighting model
Use the current composite financial performance target already in place:

earnings growth

TSR

ROE

Do not change the target definition in this phase.

Objective:

Estimate, within each sector (or fallback classification level), which Schroders culture dimensions are most associated with better financial performance.

Use those relationships to derive sector-specific weights for the culture dimensions.

Implementation requirements:

Use only the Schroders mined dimensions as predictors.

Use the shrunk company-dimension scores as predictors, not the raw scores.

Use only company-dimension inputs that are Tier A or Tier B for published model estimation.

If a company has too many missing/insufficient dimensions, exclude it from sector model estimation.

Modeling requirements:

Start with a regularized linear model, preferably ridge regression, because it is more stable under correlated predictors and preserves all dimensions rather than dropping them arbitrarily.

Standardize predictors within each sector before model fitting.

Cross-validate the regularization parameter within sector where feasible.

If sector sample size is too small for a stable sector-only model, shrink sector coefficients toward broader-group coefficients:

subindustry toward industry

industry toward sector

sector toward global Schroders prior

Make this hierarchical fallback explicit in code and logs.

Store for each sector / classification bucket:

sector_model_level_used (subindustry / industry / sector / global fallback)

n_companies_model

predictor_standardization_params

ridge_alpha_selected

dimension_weight_final

model_r2_in_sample

cross_validated_performance_metric

coefficient_stability_metric if feasible

10) Create single sector-relative culture factor score
For each company, create a single sector-relative Schroders culture factor score using the sector-specific learned weights.

Implementation:

Multiply the company’s shrunk dimension scores by the final sector-specific dimension weights.

Sum across included dimensions.

Standardize the final score within sector.

Output:

raw weighted sum

within-sector z-score

within-sector percentile rank

Store:

schroders_factor_raw

schroders_factor_sector_z

schroders_factor_sector_pctile

Important:

These scores are not intended to be compared across sectors.

All ranking logic should therefore operate within the relevant peer group only.

12) Add concentration risk checks
Implement concentration controls so that a company score is not driven by a tiny amount of text.

At minimum, compute:

share of dimension score driven by top 5 contributing terms

share driven by top 5 contributing reviews

Initial publication rule:

If either concentration share exceeds 30% on too many dimensions, downgrade reliability by one tier.

Make exact downgrade rule configurable.

13) Add overlap / multicollinearity gates
Before finalizing the active dimension set for the factor model, run overlap diagnostics on the mined Schroders dimensions.

Requirements:

Compute pairwise correlations across company-level dimension scores.

Compute VIFs within each sector model.

Flag dimensions for review if:

absolute pairwise correlation > 0.75

or VIF > 4

Treat VIF > 5 as strong warning and VIF > 10 as failure requiring remediation; common rules of thumb treat values above 5 as concerning and above 10 as serious multicollinearity.

If a dimension breaches thresholds:

do not automatically delete it;

instead create a diagnostics table with:

offending dimension

correlated counterpart(s)

correlation value

VIF

suggested action: keep / merge-review / downweight / exclude-from-model

We want a governed workflow, not automatic silent deletion.

14) Add bootstrap stability diagnostics
Because this is intended as an investment signal, add stability diagnostics around the final sector-relative factor.

At minimum:

Bootstrap companies within each sector.

Refit sector weighting model repeatedly.

Recompute company sector-relative factor ranks.

Store:

mean rank

rank standard deviation

percentile-rank standard deviation

inclusion frequency in top quintile / bottom quintile

Initial publication guidance:

High reliability should require relatively stable ranks.

Low stability should downgrade publication tier even if raw evidence counts look acceptable.

Why these instructions are justified
The mined Schroders dictionary is the right production base because it has far better empirical coverage and lower redundancy than the expert dictionary. The expert dictionary is too sparse for robust company-level inference, while the mined dictionary already reaches non-zero coverage for nearly all companies on nearly all dimensions. Your current aggregation method is “mean of mentions,” which makes low-review or low-hit companies especially vulnerable to unstable estimates, so adding evidence tiers and shrinkage is essential before using the factor externally. The bootstrap diagnostics also show that stability is not automatic, so rank-stability checks should be a formal part of the rebuilt framework.
